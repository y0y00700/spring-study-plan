## 설명할 수 있게 된 것

- Handler는 현재 요청을 실제로 처리하도록 HandlerMapping이 선택한 대상이다.
- HandlerMapping은 요청 정보를 바탕으로 Handler를 탐색하고 반환한다.
- DispatcherServlet은 등록된 HandlerAdapter 후보를 순회하며 각 Adapter의 `supports(handler)`를 호출한다.
- `supports(handler)`는 이미 선택된 Handler의 타입과 호출 규약을 현재 Adapter가 지원하는지 판단한다.
- `supports()`가 처음으로 `true`를 반환한 HandlerAdapter가 선택된다.
- 선택되지 않은 Adapter의 `handle()`은 실행되지 않는다.
- 선택된 HandlerAdapter의 `handle()`이 자신이 아는 호출 방식을 적용하여 Handler의 실제 처리 메서드를 호출한다.
- HandlerAdapter의 `handle()`과 Handler의 실제 처리 메서드는 서로 다른 계층의 호출이다.
- HandlerMapping이 `null`을 반환하면 Handler가 없으므로 HandlerAdapter 탐색도 시작되지 않는다.
- HandlerExecutionChain은 Handler와 Interceptor들을 담으며 HandlerAdapter를 매핑하는 객체가 아니다.
- DispatcherServlet은 구체적인 Handler의 호출 방법을 직접 알지 않고, Handler 탐색과 호출을 HandlerMapping과 HandlerAdapter에 위임한다.
- 새로운 Handler 호출 규약이 추가되면 이를 지원하는 HandlerAdapter를 확장할 수 있으므로 DispatcherServlet의 공통 흐름을 수정하지 않아도 된다.
